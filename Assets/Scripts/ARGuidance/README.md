# AR Guidance & UI (Student 4)

Floor arrows, waypoint/destination indicators and the 2D navigation UI.
Runs on mock navigation in a normal Unity scene, no AR device needed.

## Try it

1. Open `Assets/Scenes/ARGuidanceDemo.unity`.
2. Set the Game view to a portrait size (e.g. 1080x1920).
3. Press Play. Pick a destination and tap **Start navigation**.
4. Use the **Demo controls** panel (left) to fake device events:
   - **Scan marker (localized)**: the demo starts unlocalized, so navigation waits in *Scanning* until you press this.
   - **Lose tracking**: *Relocalizing*, arrows fade, orange warning.
   - **Simulate drift / Recalibrate**: moves the AR alignment off the corridor and back.
   - Walk speed, auto walk, camera (Overview / Follow / First person).

Everything in the scene and the prefabs is generated by
**Campus Navigation > AR Guidance > Build Demo Scene** (also *Build UI Prefab*,
*Build Route Prefabs*). Rerunning overwrites hand edits to those assets.

## Folders

| Path | What |
| --- | --- |
| `Scripts/ARGuidance/Route` | `IRouteRenderer`, `ARPathRenderer`, `RouteArrowLayout`, `RouteMarker`, `NavigationRouteBinder` |
| `Scripts/ARGuidance/UI` | `DestinationSelector`, `NavigationUI`, `NavigationUIText`, safe area / adaptive layout |
| `Scripts/ARGuidance/Alignment` | `ICampusAlignment`, `ICampusPositionProvider`, editor alignments |
| `Scripts/ARGuidance/Demo` | Demo-only scripts (map preview, camera, control panel) |
| `Scripts/ARGuidance/Editor` | Prefab / scene builders |
| `Scripts/Navigation` | `INavigationService` contract + `Mock/` (placeholder for Student 3) |
| `Scripts/Integration` | `CoordinateMapperAlignment`: adapter to Student 1's `CoordinateMapper` |
| `ARGuidance/` (assets) | Generated prefabs, sprites, materials, arrow mesh |

`CampusNavigation.ARGuidance` and `CampusNavigation.Navigation` have their own asmdefs.
Localization is in Assembly-CSharp, which asmdefs cannot reference, so it is
reached through the adapter in `Scripts/Integration`.

## Interfaces (proposal section 6)

- `IRouteRenderer`: `DisplayRoute(campusWaypoints, alignment)`, `HighlightNextWaypoint(index)`,
  `ClearRoute()`, plus `SetDimmed(bool)` for uncertain tracking.
  `HighlightNextWaypoint(waypointCount)` means *arrived*: arrows hide, destination stays.
- `INavigationService`: `StartNavigation(route)` (not `Start`, to avoid clashing with
  `MonoBehaviour.Start`), `UpdatePose(campusPose)`, `SetLocalizationReliable(bool)`,
  `StopNavigation()`, `RestartNavigation()`, `State`, `CurrentInstruction`,
  `CurrentWaypointIndex`, `RemainingDistance`, `Progress` and change events.
- All positions passed between modules are campus-local meters; only the renderer converts to world space.

## For Student 3 (navigation engine)

Implement `INavigationService` (a MonoBehaviour implementing it directly is fine), put it in the
scene and point `NavigationUI`, `DestinationSelector` and `NavigationRouteBinder` at it.
Then `Scripts/Navigation/Mock` can be deleted. The UI only uses the interface.
`MockNavigationService` + its tests show the expected behaviour.
